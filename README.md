# Reporting Web

New web app for the Reporting Tool migration. Fresh project, does not affect `../Reporting-Tool`.

## Stack

- Astro 7 + React 19 + TypeScript (strict)
- Tailwind CSS 4 + shadcn with Base UI (base-nova preset, lucide icons)
- ESLint + Prettier
- Vitest + Testing Library + jsdom + Playwright
- Convex (password auth, staff account management, reporting domain schema)
- pnpm (`pnpm@11.24.0`, engines: node >=22.12, pnpm >=9)
- shadcn skill installed at `~/.agents/skills/shadcn/`, Convex AI skills in `.agents/skills/` + `.claude/skills/`

## Scripts

```sh
pnpm dev             # start Astro and Convex
pnpm build           # production build
pnpm lint            # eslint
pnpm format          # prettier --write
pnpm test            # vitest run
pnpm test:watch      # vitest watch
pnpm e2e             # playwright
pnpm dlx shadcn@latest add button --yes   # add UI components (base, not radix)
pnpm dlx convex ai-files status           # check Convex AI files
```

## Convex

Convex is set up against a dev deployment. `CONVEX_DEPLOYMENT` and `CONVEX_URL` live in `.env.local` (not committed). Use `pnpm dlx convex dev` to sync functions.

- `convex/schema.ts` defines the domain schema: staff profiles, clients, clinics (with embedded `sheetColumns` and `qaGroupKeys`), report types, and report runs. Report types are rows: `ownerUserId: null` marks a built-in that administrators edit and every operator can run, any other owner keeps the type private to that account. Each run stores `reportTypeName` next to the type id, so history stays readable after a rename or a delete.
- `convex/auth.ts` uses the Password provider with a username and password. The provider only needs an opaque account id, so the username travels in its `email` field and lands on the library-owned `users.email` column; sign-in reads it back as `username`. Nothing validates that the value looks like an address. Email verification is not available, so new accounts are gated by admin activation instead (first user becomes an active admin, later sign-ups start disabled as operators).
- `convex/staffAccounts.ts` + `convex/model/staff.ts` implement staff account management (roles, status, admin-guarded queries). `staffProfiles` is the single permission source; backend functions check role/status there instead of grant tables.
- `convex/migrations/` holds one-shot internal mutations, run by hand from the CLI. They are listed in the order a deployment needs them:
  - `pnpm dlx convex run migrations/reportTypesSeed:run` creates the built-in report types "Pending audit" and "Pending to execute". A fresh deployment needs it once; running it twice does nothing.
  - `pnpm dlx convex run migrations/executeReportConditions:run` copies the row rules of the seed into the built-in "Pending to execute" that the seed left without rules. A type anyone saved keeps what it holds, including one whose rules were cleared on purpose, so running it twice does nothing.
  - `pnpm dlx convex run migrations/reportTypesCleanup:run` deletes report rows written before report types were stored per owner. Run it while the previous schema is deployed, before the release that changes `reportTypes` and `reportRuns`: the first push after a schema change validates every stored document, so a deployment that still holds the old rows rejects the new schema.
  - `pnpm dlx convex run migrations/backfillClientClinicCounts:run` stores how many clinics each client owns, which is the count the Clients tab lists. It reads the clinics themselves, so running it twice changes nothing. Run it once this release is live, and after `pnpm import:ccc-directory --execute` if that runs: the import counts the clinics it writes, but a directory wiped and rebuilt by an older script would leave the counts behind. `clients.clinicCount` stays optional in `convex/schema.ts` until the backfill has run everywhere, and tightens to `v.number()` afterwards.
- `convex/_generated/` is gitignored and regenerated by `convex dev`.
- Read `convex/_generated/ai/guidelines.md` before writing Convex code; it overrides prior training data.

## Decisions

- Path alias `@/*` -> `src/*` via `tsconfig.json`.
- Tailwind via `@tailwindcss/vite` + `src/styles/global.css` (imports `shadcn/tailwind.css`, `tw-animate-css`, `@fontsource-variable/geist`).
- shadcn config in `components.json` (base-nova, base, cssVariables, neutral). UI components in `src/components/ui/` use `@base-ui/react` primitives, not Radix.
- Theming: class-based dark mode, follows the device preference by default with a light/dark/system toggle (`src/lib/theme.ts`, `src/components/theme/ThemeToggle.tsx`).
- Languages: English and Spanish, resolved in the client (no locale in the URL). The device preference picks the first one; a signed-in user's choice is stored on `staffProfiles.language` and wins on every device. Catalogs live in `src/lib/i18n/messages/`, the provider and hooks in `src/lib/i18n/context.tsx`, and the switcher in `src/components/i18n/LanguageToggle.tsx`. Backend errors travel as codes (`convex/model/appErrors.ts`) and are rendered in the active language by `src/lib/i18n/errors.ts`.
- `pnpm-workspace.yaml` allowBuilds: esbuild=true.
